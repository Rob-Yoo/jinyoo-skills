사용자가 준 주제를 주니어에게 설명하는 HTML 페이지 하나로 만든다. 주니어는 주제에 맞는 직군이다: 개발 주제면 주니어 개발자, 기획 주제면 주니어 기획자, 디자인 주제면 주니어 디자이너. 주니어는 똑똑하고 실제 용어를 받아들이지만 이 맥락을 모른다. 그래서 **실제 예시** 하나를 처음부터 끝까지 따라가며 실제 동작을 보여준다.

## 실제 예시 고르기

주제가 현재 프로젝트에 있으면 프로젝트의 실제 코드·화면·문서에서 예시를 고른다. 예시로 쓰는 코드와 파일은 직접 열어 확인한 것만 쓴다. 프로젝트와 무관한 주제면 작고 구체적인 일반 예시를 쓴다: 실제 값, 실제 화면, 실제 상태.

## 페이지 구성

1. **한 줄 요약**: 이것이 무엇이고 어떤 실제 문제를 푸는지.
2. **용어**: 이 페이지에서 쓸 핵심 용어 3~5개를 한 줄씩 정의한다. 본문은 정의한 용어로 쓴다.
3. **실제 예시 따라가기**: 페이지의 본체. 실제 예시가 단계별로 움직이는 애니메이션과 단계마다 한 줄 설명.
4. **조건이 바뀌면**: 예시의 입력이나 조건 하나를 바꿨을 때 결과가 어떻게 달라지는지 1~2개.
5. **정리**: 핵심 세 줄과 더 볼 곳 (공식 문서, 예시로 쓴 프로젝트 파일 경로).

문장은 짧게, 한 문장에 한 가지 생각만 담는다. 비유는 실제 설명을 마친 뒤 "~와 비슷하다" 한 줄 연결로만 쓴다.

## 애니메이션

애니메이션을 풍부하게 쓴다. 움직이는 것은 실제 예시의 실제 대상이다: 개발이면 값과 데이터의 이동, 기획이면 사용자 흐름, 디자인이면 상태 전환.

- 재생, 일시정지, 한 단계씩 넘기기 컨트롤을 둔다.
- 각 단계에서 지금 일어나는 일을 한 줄로 화면에 보여준다.
- `prefers-reduced-motion` 이면 단계별 정지 화면으로 보여준다.
- CSS 와 바닐라 JS 만으로 self-contained 하게 만든다.

## 출력

Artifact 를 발행할 수 있는 환경이면 artifact-design 스킬을 먼저 읽고 Artifact 로 발행해 링크를 준다. 그렇지 않으면 HTML 파일을 `mktemp -d` 로 만든 디렉토리에 저장하고, 열어 주고 (macOS: `open`), 경로를 알려준다.
