---

사용자가 준 명세나 작업 단위 (목표, 범위, 완료 기준) 를 구현한다. 커밋은 하지 않는다: 커밋 방식은 프로젝트와 사용자에게 맡긴다.

1. **구현 방식**: 호출한 쪽이 합의한 테스트 seam 을 넘겼으면 테스트 주도로 정해진 것이다. 넘기지 않았으면 구현 전에 사용자에게 묻고 답을 기다린다: 이 스킬 디렉토리 기준 `../tdd/SKILL.md` 로 테스트 주도 구현을 할지, 테스트 없이 구현하고 빌드와 기존 테스트로 확인할지.
2. **구현**: 테스트 주도면 `../tdd/SKILL.md` 를 따른다. 합의한 seam 이 있으면 그 seam 에서만 테스트하고, 없으면 tdd 대로 seam 을 먼저 합의한다. 루프를 쓸 수 없는 변경은 tdd 의 기준대로 빌드와 기존 테스트로 확인한다. 테스트 없이 하기로 했으면 바로 구현한다.
3. **검증**: 타입 체크와 지금 다루는 테스트 파일은 자주 돌리고, 전체 테스트는 끝에 한 번 돌린다. 명령은 프로젝트의 지침 문서, `Makefile`, `package.json` 등에서 찾는다. green 이 될 때까지 고친다.
4. **리뷰**: `../impl-review/SKILL.md` 를 따른다. 기준점과 명세는 호출한 쪽이 준 것을 쓰고, 없으면 impl-review 대로 정한다.
5. **반영**: 리뷰 지적을 받아들일 것과 넘길 것으로 나눠 이유와 함께 알린다. 받아들인 지적은 고치고 3 의 검증을 다시 돌린다.

끝나면 무엇을 구현했는지, 구현 방식 (테스트 주도면 테스트한 seam), 검증 결과, 리뷰에서 받아들인·넘긴 지적을 보고한다.
