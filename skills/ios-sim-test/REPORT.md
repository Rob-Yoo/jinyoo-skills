# 보고서

[`ios-sim-test`](SKILL.md) 의 마지막 단계다: 모든 항목에 판정이 붙은 뒤 읽는다.

## 영상 가공

`xcrun simctl io <UDID> recordVideo` 는 화면이 바뀔 때만 프레임을 쓴다 (VFR). 그래서 파일 크기로 화면 변화 여부를 가늠할 수 있다. 단 절대 크기가 아니라 **같은 화면에서 입력 없이 같은 길이로 찍은 기준 녹화**와 비교한다: 정적인 앱 화면은 수십 KB 지만, 홈 화면처럼 계속 움직이는 배경이 있으면 입력이 없어도 MB 단위가 나온다 (실측). 녹화 시작에 지연이 있어 입력 시각과 영상 시간이 정확히 맞지 않는다 (지연 크기는 미측정).

- VFR 영상에 `-ss` 로 바로 찾아가면 순서가 뒤섞여 보인다. 먼저 `-vf fps=30` 으로 CFR 로 바꾼 뒤 자른다.
- 위치 찾기: `-vf "fps=4,scale=100:-1,tile=16x4"` 로 한 장에 몰아 보고, 그 시간대만 전체 해상도로 뽑는다.
- 보고서용 클립: 이 스킬 디렉토리의 `scripts/trim-still.sh <원본> <클립>` 으로 만든다. 멈춘 구간만 짧게 줄이고 움직이는 구간은 그대로 둔다. 출력의 결과 길이가 원본보다 짧으면 캡션에 "멈춘 구간 줄임" 을 적는다. 멈춘 시간 자체가 판정 근거인 항목 (지연, 자동으로 사라지기까지의 시간) 은 `trim-still.sh <원본> <클립> 0 100000` 으로 줄이지 않은 클립을 만든다. 클립 10여 개와 이미지 여러 장이 1MB 안팎이다.
- 프레임 분해: 변화 구간을 여러 프레임으로 뽑아 가로로 이어 붙인다.
- 크기 변화 (글자 확대 등) 는 같은 해상도·같은 크롭 영역으로 전후 스크린샷을 세로로 붙인 이미지가 가장 잘 읽힌다. 픽셀 행을 스캔해 경계 x 를 비교하면 숫자 근거도 된다.
- 이미지 크롭은 ffmpeg `crop=w:h:x:y` 로 한다. `sips --cropOffset` 은 실측에서 기대와 다른 영역을 잘랐다.
- ffmpeg 빌드에 `drawtext` 필터가 없을 수 있다 (`ffmpeg -filters | grep drawtext`). 없으면 프레임에 시간 표기를 넣지 말고 캡션에 적는다.

## 보고서 구조

self-contained HTML 하나와 `media/` (mp4, jpg) 로 만든다. 미디어는 `media/` 기준 상대 경로로 넣는다. 색은 CSS 변수로 정의하고 `prefers-color-scheme` 으로 라이트·다크를 둘 다 정해, 시스템 설정을 따라 바뀌게 한다.

- **머리**: 대상 (체크리스트 출처), 환경 (기기, OS, 서버, 계정·대상 데이터), 브랜치와 커밋 여부.
- **순서**: 요약 표와 본문 모두 실패 → 판단 필요 → 확인 불가 → 통과 순이다. 같은 판정 안에서는 체크리스트 번호 순, D 번호는 그 뒤다. 본문은 "실패 · 판단 필요 · 확인 불가" 와 "통과" 두 그룹 머리 아래 둔다.
- **요약 표**: 번호 (D 번호 포함), 항목, 판정 칩. 칩을 누르면 해당 절로 간다.
- **항목 절**: 제목은 항목을 문장으로 ("두 번 탭하면 이모지가 터지고 글자가 커진다"), 판정 칩, 근거 사실 목록 (데이터 값은 전후로), 영상 (`controls muted loop playsinline`), 프레임 분해 이미지 (가로 스크롤), 전후 비교 이미지.
- **실패·판단 필요 항목**: "지금 모습" 과 "기대 모습" 이미지를 같은 해상도·같은 크롭 영역으로 잘라 나란히 붙인다 (2열, 좁은 화면에서는 1열). 캡션 색으로 구분한다: 기대는 통과 색, 지금은 실패 색. 기대 모습 자료가 없으면 그 자리에 "기대 모습 자료 없음" 과 이유를 적는다.
- **판단 필요 항목**: 경우를 표로 나누고 선택지를 적는다. 결정이 나면 결정과 날짜를 적고, 판정을 결정에 맞춰 실패나 통과로 바꿔 순서대로 옮긴다.
- 체크리스트 출처에 데모·시연 전용 UI 가 섞여 있으면 "구현 대상 아님" 과 그 근거 (파일·줄) 를 미리 적는다. 읽는 사람이 데모 UI 를 앱 화면으로 오해하지 않게.
- **끝 절**: 확인 방법과 도구 한계, 바꿨다가 되돌린 환경, 서버에 남긴 흔적 (보낸 메시지, 바뀐 값과 횟수). 확인하지 못한 항목은 확인 불가 판정으로 본문에 둔다.

## 전달

프로젝트 지침이 외부 게시를 막으면 (누설 금지 등) 아래의 로컬 HTML 로 전달한다. 그 밖에 Artifact 를 발행할 수 있는 환경이면 HTML 을 Artifact 로, `media/*` 를 함께 올리는 파일로 발행하고 링크를 준다. 발행 결과가 비공개면 다른 사람이 보려면 공유해야 한다고 알린다. Artifact 가 없는 환경이면 작업 디렉토리의 HTML 을 열어 주고 (macOS: `open`) 경로를 알린다.

"판단 필요" 결정이 나면 같은 파일을 고쳐 처음과 같은 방식으로 다시 전달한다. Artifact 면 같은 경로로 재발행해 링크를 유지한다.
