사용자가 준 체크리스트 (검수 항목, 요구사항 목록, 또는 명세 경로) 를 iOS 시뮬레이터에서 직접 조작해 확인한다. 항목마다 판정과 근거를 붙인 HTML 보고서가 산출이다. 시뮬레이터 조작과 녹화에는 macOS 로컬 도구 (`xcrun simctl`, Maestro, osascript, CGEvent) 가 필요하다. 샌드박스 안에서 명령을 실행하는 환경이면 이 명령들은 샌드박스 밖 실행 (권한 상승) 으로 요청한다. Codex 환경에서는 아직 실측하지 않았다.

## 핵심 규칙

- **입력 전후로 스크린샷을 읽는다.** 다음 입력은 방금 읽은 실제 화면을 보고 정한다. 화면을 보지 않고 넣은 입력은 화면이 바뀐 사이 엉뚱한 곳에 떨어져 다른 것을 잰다.
- **판정은 셋 중 하나다**: 통과 / 판단 필요 / 확인 불가. 판정마다 근거 (영상, 프레임 분해, 전후 비교 이미지, 데이터 값) 를 붙인다. 결과가 기대와 달라 의도인지 결함인지 갈리는 항목은 "판단 필요" 로 두고 경우를 나눠 사용자에게 넘긴다. 시뮬레이터로 확인할 수 없는 것 (햅틱, 실기기 성능) 은 "확인 불가, 실기기 필요" 다.
- **다른 사람 화면에 보이는 입력은 미리 확인받는다**: 메시지 전송, 글 게시, 남의 데이터를 바꾸는 입력. 검증 입력은 서버에 실제로 쓰인다. 내 화면에서만 바뀌는 입력은 그대로 진행한다.
- **바꾼 환경은 되돌린다.** 시뮬레이터 설정이나 macOS 권한을 바꾸기 전에 원래 값을 기록하고, 끝나면 되돌린 뒤 보고한다.
- 경로는 전부 절대경로로 쓴다. 산출물은 `mktemp -d` 로 만든 작업 디렉토리에 모은다.

## 단계

1. **준비**
   - 시뮬레이터 UDID: 프로젝트 지침 문서에 정해져 있으면 그것을, 없으면 `xcrun simctl list devices booted` 에서 고른다. 여러 대면 사용자에게 묻는다.
   - 앱을 프로젝트 지침 문서의 빌드 명령으로 빌드·설치·실행한다. 로그인 같은 사전 상태와 대상 환경 (서버, 계정) 은 사용자에게 확인한다.
   - 체크리스트를 번호 매긴 항목으로 정리하고, 항목마다 무엇을 보면 판정할 수 있는지 (화면 변화, 데이터 값) 적는다.
   - 시나리오 경로에서 누르고 읽을 화면 요소를 전부 뽑아, `accessibilityIdentifier` 가 없는 요소에 코드로 달고 그 빌드를 설치한 뒤 시작한다. id 를 단 것도 코드 변경이라 보고에 적는다.
2. **이동**: 대상 화면까지 Maestro 로 간다. 요소는 id 로 누른다 (`tapOn: {id: ...}`). 진행 중 id 없는 요소를 만나면 그 자리에서 달고 다시 빌드해 이어 간다. 단계마다 스크린샷을 읽고 다음 입력을 정한다.
3. **항목 확인**: 항목마다 녹화하며 입력을 넣는다 (이 스킬 디렉토리의 `scripts/rec.sh`). 녹화, 스크린샷, 필요하면 앱 데이터로 판정한다.
   - 기본 근거는 화면이다. 서버 반영처럼 화면 밖 사실이 필요하면 `xcrun simctl get_app_container <UDID> <bundle id> data` 아래 앱 저장소 (sqlite, plist 등) 를 읽는다. 어느 파일인지는 기능마다 그때 찾고, 그 경로를 보고서에 적는다. 계정 캐시가 섞여 있을 수 있으므로 데이터는 화면과 함께 본다.
   - 입력이 기대대로 들어가지 않거나 화면 변화가 없으면 이 스킬 디렉토리의 `INPUT.md` 를 본다. "무반응" 으로 판정하기 전에 입력 방법부터 의심한다.
   - 키보드, 동작 줄이기 같은 시뮬레이터 설정을 바꿔야 하는 항목은 `SIM-SETUP.md` 를 본다.
4. **원복**: 바꾼 설정과 권한을 되돌리고, 되돌린 결과를 확인한다.
5. **보고서**: 모든 항목에 판정이 붙으면 `REPORT.md` 를 따라 영상을 가공하고 보고서를 만든다.

## 완료

체크리스트의 모든 항목에 판정과 근거가 붙고, 바꾼 환경이 원래대로 돌아오고, 보고서가 사용자에게 전달됐을 때 끝난다. "판단 필요" 항목은 사용자의 결정이 나면 보고서에 반영해 같은 경로로 다시 전달한다.
