# Code Analyze

iOS 앱 코드에 대한 질문에, 코드가 직접 보여주는 것과 거기서 추론한 것을 갈라서 답한다. 파일 하나를 읽으면 답이 나오는 사실 확인은 이 절차 없이 바로 답한다.

기존 코드에서 결함 후보를 찾는 요청이면 [AUDIT.md](AUDIT.md) 를 읽고 그 절차로 진행한다. 등급과 재확인은 이 문서를 따른다.

이 스킬은 읽기 전용이다: 코드는 그대로 두고, 빌드와 기존 테스트 실행은 근거를 얻는 수단으로 쓴다. 산출은 질문의 답이다. 수정 계획은 사용자가 요청할 때 따로 세운다.

## 등급

답의 모든 주장에 셋 중 하나를 붙인다:

- **근거**: 코드, 설정, 테스트, 빌드 출력이 직접 보여준다. `file:line` 을 단다.
- **추론**: 근거에서 이끌었지만 코드만으로는 확정되지 않는다 (런타임 동작, 서버 응답, 타이밍, 기기 상태). 기댄 근거의 `file:line` 과, 확정하려면 무엇을 실행하거나 확인해야 하는지 단다.
- **모름**: 근거가 부족하다. 확인 방법을 단다.

추론은 "~로 보인다", "~일 가능성이 높다" 처럼 확정되지 않았음이 문장에서 드러나게 쓴다.

## 절차

1. 질문을 한 문장으로 다시 쓰고, 답이 될 수 있는 설명을 지금 모두 적는다.
2. 설명마다 지지하는 근거와 기각하는 근거를 찾는다. 하나가 확인돼도 나머지를 계속 검토한다: 원인은 여럿일 수 있다.
3. 서브에이전트에 나눠 맡겼으면, 받은 주장마다 그 `file:line` 을 직접 읽어 확인한 것만 답에 쓴다. 확인되지 않은 주장은 버리거나 모름으로 내린다.
4. 아래 형식으로 답한다.

## 답 형식

채팅으로 답한다:

```
질문: <한 문장>
답: <결론 먼저, 두세 문장>

| 순위 | 설명 | 등급 | 바탕 |      ← 설명이 둘 이상일 때만

근거
- `path:line` — 이 위치가 직접 보여주는 것
추론
- <주장> — 기댄 근거, 확정 방법
모름
- <질문> — 확인 방법
```

## 완료 기준

다음을 모두 만족할 때 끝난다:

- 답의 모든 주장에 등급이 있고, 근거에는 `file:line` 이 있다.
- 설명이 여럿이면 각 설명에 순위와 그 바탕이 있거나, 기각한 근거가 있다.
- 추론과 모름마다 확정·확인 방법이 한 줄씩 있다.
- 서브에이전트가 낸 주장은 모두 직접 확인했다.
