# Close

모든 Phase 가 `[완료]` 된 미션을 마무리한다. 순서대로 한다. ADR 을 다 쓰기 전에는 wip 문서를 지우지 않는다: ADR 의 재료가 거기에만 있다.

1. 모든 Phase 의 변경이 부모 브랜치에 머지됐는지 확인한다. 안 된 Phase 가 있으면 알리고 멈춘다.
2. Overview 헤더의 부모 브랜치로 전환해 최신으로 맞춘다.
3. ADR 후보를 만든다 (아래).
4. 사용자가 고른 후보만 `../grill-with-adr/ADR-FORMAT.md` 대로 쓴다. 이유와 버린 대안은 Plan 과 `기록` 에 적힌 것만 쓴다.
5. 사용자 확인을 받고 `Docs/wip/plan/<slug>.md` 와 `Docs/wip/task/<slug>/` 를 지운다.
6. 커밋 방식은 사용자에게 맡긴다.
7. 부모 브랜치를 base 브랜치로 PR 할 차례라고 알린다. 두 이름은 지우기 전 Overview 헤더에서 읽어 둔다.

## ADR 후보

재료는 Plan 의 설계 결정 표 전체와 Overview 의 모든 Phase `기록` (`[결정]`, `[변경]`, `[발견]`) 이다.

- 같은 주제는 후보 하나로 묶는다. Plan 의 결정을 `[변경]` 이 바꿨으면 최종 결정은 `[변경]` 이고, 계획했던 안은 버린 대안이 된다.
- 후보마다 ADR-FORMAT 의 세 조건을 근거와 함께 표시한다.
- 세 조건을 통과하지 못한 항목도 `제외: <사유>` 로 목록에 남긴다. 재료의 모든 항목이 후보나 제외 중 하나에 나타나야 한다: 이 목록이 누락 점검이다.
- 미션 중 에이전트 문서에 반영된 규칙이 있으면 ADR-FORMAT 대로 포인터 한 줄을 함께 단다.
