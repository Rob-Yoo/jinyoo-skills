사용자가 준 아이디어로 PRD 를 쓴다. 산출물은 `Docs/wip/prd/<slug>.md` 하나다. 같은 slug 의 PRD 가 이미 있으면 새로 만들지 않고 그 문서를 고친다.

PRD 는 무엇을, 왜 만드는지만 담는다. 기술 설계, 작업 분할, 화면 세부, 일정과 담당자는 쓰지 않는다. 요구사항은 사용자가 겪는 동작으로 쓰고, 프레임워크나 API 이름은 쓰지 않는다.

## 단계

1. **읽기**: 아이디어, 프로젝트 지침 문서, 기존 앱 코드 (있으면) 를 읽는다. 찾을 것: 대상 플랫폼, 이 기능이 붙을 자리, 이미 있는 비슷한 기능, 앱이 이미 쓰는 시스템 기능 (위젯, 알림 등).
2. **질문**: 이 스킬 디렉토리 기준 `../grilling/SKILL.md` 를 읽고 그대로 진행한다. 묻는 것은 무엇과 왜뿐이고 구현 방법은 묻지 않는다. 선행 관계는 이렇다: 기능 이름과 slug (영문 kebab-case), 대상 사용자 → 목표와 핵심 시나리오 → 시스템 통합 기능의 채택 여부. 시스템 통합은 핵심 시나리오가 정해진 뒤에 `APPLE-FIT.md` 의 후보를 훑어 채택·보류할 것만 추천안과 함께 묻는다.
3. **작성**: 아래 형식으로 쓴다. 상태는 `초안` 이다. "Apple 플랫폼 경험" 은 이 스킬 디렉토리의 `APPLE-FIT.md` 를 읽고 채운다. 접근성 수용 기준은 사용자에게 묻지 않고 초안을 쓴다.
4. **검토**: 문서 경로를 알려주고 검토받는다. 피드백을 반영하고, 사용자가 더 고칠 것이 없다고 하면 상태를 `확정` 으로 바꾼다. 끝에 "PRD 는 `Docs/wip/prd/<slug>.md` 에 있다" 고 알린다.

## 규칙

- **수용 기준은 확인할 수 있는 문장이다.** "~하면 ~가 보인다", "~에서 ~할 수 있다" 처럼 누가 봐도 통과·실패를 가를 수 있게 쓴다. "잘 동작한다", "지원한다" 는 수용 기준이 아니다.
- **정하지 못한 것은 정하지 않는다.** 대화와 코드로 답이 안 나오는 것은 "열린 질문" 에 적는다.
- **대화에 없는 이유는 쓰지 않는다.** 목표는 사용자가 말한 것으로 쓴다.

## PRD 형식

```markdown
# <기능명> PRD

> 작성: YYYY-MM-DD · 상태: 초안 | 확정 · 플랫폼: <iPhone 등>

## 목표
- <이 기능이 끝나면 달라지는 것> · 지표: <측정 방법, 없으면 생략>

## 사용자 시나리오
1. <사용자가 ~하면 ~한다> (핵심 흐름 1~3개)

## 요구사항
| ID | 요구사항 | 수용 기준 |
|----|----------|-----------|
| FR-1 | ... | ... |

## Apple 플랫폼 경험

### 접근성
| ID | 항목 | 이 앱에서의 요구 | 수용 기준 |
|----|------|-----------------|-----------|
| A11Y-1 | VoiceOver | ... | ... |

### 시스템 통합
| ID | 기능 | 판정 | 이유 | 수용 기준 |
|----|------|------|------|-----------|
| SYS-1 | 위젯 | 채택 | ... | ... |

## 열린 질문
- <아직 못 정한 것>
```

- ID 는 `FR-n`, `A11Y-n`, `SYS-n` 이다. 문서를 고칠 때 이미 붙은 ID 는 바꾸거나 다시 쓰지 않는다.
- 접근성 표에는 `APPLE-FIT.md` 의 접근성 항목을 모두 판정한 뒤, 이 앱에 넣을 항목만 적는다. 행마다 `A11Y-n` ID, 이 앱에서의 요구, 수용 기준을 붙인다.
- 시스템 통합 표에는 `APPLE-FIT.md` 의 후보를 모두 판정한 뒤, `채택` 과 `보류` 만 적는다. 판정은 `채택`, `보류`, `해당 없음` 이다: `보류` 는 이 앱에 어울리지만 이번에 하지 않는 것, `해당 없음` 은 이 앱에 어울리지 않는 것이다. 채택한 기능만 ID 와 수용 기준을 붙이고, 보류한 기능은 ID 칸을 `—` 로 두고 수용 기준 칸을 비운다. 다른 기능의 채택에 기대는 기능 (예: 알림을 채택하면 필요해지는 집중 모드) 은 그 기능과 같은 판정을 따르고 이유에 그렇게 적는다. 적을 기능이 없으면 표 대신 "채택·보류한 기능 없음" 한 줄을 쓴다.
- 플랫폼이 iPhone 이 아니면 "Apple 플랫폼 경험" 절을 빼고 그렇게 적는다.
