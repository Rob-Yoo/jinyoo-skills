# 함께 고칠 대상 실측

[`refactor-like-fowler`](SKILL.md) 의 Phase 2 branch 다: 대상 A 만 고치면 반쪽이 되는 경우 함께 고칠 B 를 찾는다. *Shotgun Surgery* 는 정의상 A 하나로 해소되지 않는다.

범위 확대 제안은 증거가 있을 때만 한다. 근거 없는 제안이 두세 번 반복되면 사용자는 제안 전체를 건너뛰고, 진짜 필요한 확대도 함께 묻힌다. 모든 숫자는 아래 명령의 실제 출력에서 가져오고, 열어보지 않은 것은 `(미확인)` 으로 쓴다. 증거가 약하면 제안 대신 백로그에 메모만 남긴다. 승인 전에는 A 밖의 파일을 읽기만 한다.

## 증거 1 — 동시 변경 결합도 (가장 강함)

*Shotgun Surgery* 는 이력으로만 증명된다. A 를 고친 커밋에서 B 도 함께 바뀌었는지 센다. 결과 옆에 측정한 ref (브랜치) 를 적는다: `git log` 는 체크아웃된 ref 를 따른다.

```bash
FILE=<A 경로>; BASE=$(basename "$FILE"); TMP=$(mktemp)
git log -n 200 --no-merges --format='%H' --follow -- "$FILE" > "$TMP"
echo "A 변경 커밋: $(grep -c . "$TMP")"
while read -r c; do
  n=$(git show --pretty=format: --name-only "$c" | grep -c .)
  [ "$n" -le 30 ] && git show --pretty=format: --name-only "$c"
done < "$TMP" | grep -vE '<생성물·lock·빌드 설정 패턴>' \
  | xargs -n1 basename | grep -vx "$BASE" | sort | uniq -c | sort -rn | head -15
rm -f "$TMP"
```

- `--follow`: A 의 과거 경로 이력까지 표본에 넣는다.
- `--no-merges`: 머지 커밋을 동반 변경에서 뺀다.
- 커밋당 30 파일 상한: 대량 rename·포맷 커밋 하나가 수백 파일을 동반으로 만드는 것을 막는다.
- 생성물·lock·빌드 설정 제외: 의존성이 바뀔 때마다 걸리는 파일은 구조적 노이즈다.
- `basename` 정규화: 파일이 옮겨진 이력이 있으면 같은 파일이 여러 경로로 쪼개져 결합도가 과소평가된다. 대신 다른 디렉토리의 같은 이름 파일이 합산되므로, 후보를 정하기 전에 `git log --format= --name-only -- '*/<basename>'` 으로 경로 갈래를 확인한다.

**기저율 보정**: 원래 자주 바뀌는 파일은 무엇과도 같이 바뀐다. 양방향을 모두 낸다.

```bash
git log --no-merges --format='%H' -- "*/<B basename>" | grep -c .   # B 총 변경 커밋
```

- A→B = 동반 수 / A 총 커밋: A 를 고칠 때 B 도 고칠 확률
- B→A = 동반 수 / B 총 커밋: 낮으면 B 는 그냥 자주 바뀌는 파일이다

**자기 저작 오염**: A 의 커밋 대부분이 이번 작업 브랜치에서 만든 것이면 결합도는 "내가 오늘 둘을 같이 고쳤다" 를 되읽을 뿐이다.

```bash
TOT=$(git log --no-merges --format=%H -- "$FILE" | wc -l | tr -d ' ')
MINE=$(git log --no-merges --format=%H <분기 기준>..HEAD -- "$FILE" | wc -l | tr -d ' ')
echo "전체 $TOT · 이번 브랜치 $MINE · 기준선 이전 $((TOT-MINE))"
```

판정 (휴리스틱이다. 항상 해당 커밋을 눈으로 확인한다):

| 조건 | 판정 |
|------|------|
| A→B ≥ 30% 그리고 B→A ≥ 30% | 강한 결합: 함께 권장 |
| B→A 만 ≥ 30% | B 가 A 에 기댄다: 약한 후보 |
| A→B 만 ≥ 30% | B 가 churn 파일일 수 있다: 증거 2·3 으로 재확인될 때만 제안 |
| 양쪽 < 15% | 제안하지 않는다 |
| A 커밋 < 10, 또는 기준선 이전 커밋 < 10 | 표본 부족·자기 저작: 결합도를 보고서에서 빼고 `결합도 = 측정 불가 (사유)` 로 적은 뒤 증거 2·3 으로 판단한다 |

## 증거 2 — 구조적 중복

같은 악취가 실제로 몇 곳에 나오는지 출현 수와 라인을 인용한다. 유사하다고 주장하지 않는다.

- *Duplicated Code*: 특징적인 코드 조각을 grep 한다.
- *Repeated Switches*: 분기 대상 타입 이름이 아니라 특징적인 case 값으로 grep 한다. 값으로 분기하는 언어에서는 타입 이름으로 찾으면 0건이 나온다.
- 출현 3곳 이상이면 A 국소 문제가 아니다 (Rule of Three). 2곳이면 메모만 한다. 테스트 코드의 출현은 따로 센다.

## 증거 3 — 손댈 지점 수

기법을 적용할 때 실제로 건드릴 호출처·참조 수다. 스텝 수와 확대 비용의 근거다. 심볼 이름만이 아니라 모듈·네임스페이스로 한정한 참조 (`<모듈>.<심볼>`) 도 함께 grep 한다: import 정리나 심볼 검색으로 잡히지 않는다.

## 증거 4 — 공유 심볼

A 와 B 가 같은 타입·키·엔드포인트를 참조하면 한쪽만 바꿀 때 어댑터가 남는다. 두 파일의 식별자 교집합으로 후보를 좁히고, 결합 주장은 그 심볼을 읽어 확인한 뒤에 한다.

## 제안 형식

후보마다 같이 하면 얻는 것과 따로 하면 생기는 비용을 둘 다 쓴다. 뒤의 것이 없으면 사용자는 판단을 미룬다.

```
### B — 함께 권장
근거   Shotgun Surgery. 동반 15 — A→B 16% (15/96) / B→A 41% (15/37), ref main
같이   Combine Functions into Class 를 두 곳에 한 번에 — 중간 어댑터 없음
따로   A 를 먼저 끝내면 B 가 옛 인터페이스를 참조 → 어댑터 1개가 남고 B 착수 때 걷어낸다
비용   스텝 +3

### C — 기각
근거   동반 11 로 상위지만 B→A 3.5% (11/318) — 기저율 노이즈
```

## 확대 승인 후

- 두 대상에 걸치는 기법은 공통 부분을 세우는 스텝부터 시작하도록 백로그를 다시 정렬한다.
- 확대는 스텝의 개수를 늘린다. 스텝 하나의 크기는 그대로다.
- 어느 스텝이 어느 대상인지 커밋 메시지에 드러낸다. 범위를 되돌릴 때 경계가 된다.
