# 시스템 규모 — 점진 교체

[`refactor-like-fowler`](SKILL.md) 의 Phase 3 branch 다: 대상이 공개 계약, 모듈 경계, 여러 모듈의 호출처에 걸칠 때. 이때 "한 기법 = 한 커밋" 으로는 스텝이 부풀어, 한 스텝에서 컴파일 오류 수십 개가 나고 되돌릴 지점이 시작점 하나뿐이 된다. 그래서 *Branch by Abstraction* (*Parallel Change*) 으로 옛 구현과 새 구현을 한동안 공존시키며 옮긴다.

## 이 레일이 필요한 경우

하나라도 해당하면 깐다:

- 바꿀 심볼이 공개되어 있고 모듈 밖 호출처가 많다 (10곳 이상이 기준선)
- 타입을 다른 모듈로 옮기거나 모듈을 새로 만든다
- 두 구현이 한동안 공존해야 한다 (데이터 소스 교체, 인터페이스 교체)
- 옮길 상태를 프레임워크가 관찰한다 (반응형 UI 바인딩, observable 프로퍼티 등). 호출처가 한 곳이어도 해당한다: 소유권을 새 타입으로 옮기고 옛 객체가 전달만 하면 컴파일과 유닛 테스트는 green 인 채로 관찰하던 화면이 갱신을 멈출 수 있다. 관찰자가 새 소유자를 관찰하게 바꾸거나, 옛 객체가 변경을 구독해 다시 알리는 배관을 먼저 세운다.

## 레일 — 4구간

```
1. 추상화 도입   옛 구현 위에 얇은 경계를 세운다. 동작 변화 0.
2. 새 구현 병행   경계 뒤에 새 구현을 추가한다. 아직 아무도 쓰지 않는다.
3. 호출처 이관   배치로 옮긴다. 배치마다 커밋하고 green.
4. 옛 구현 제거   호출처 0 을 grep 으로 증명한 뒤 지운다.
```

각 구간의 끝이 멈출 수 있는 지점이다. 3구간 중간에 멈춰도 절반은 새 경로, 절반은 옛 경로로 둘 다 green 이어야 한다. 멈추면 깨지는 구간이 생겼다면 레일을 잘못 깐 것이다.

- **1구간**: 옛 타입의 시그니처를 그대로 베낀 경계를 만든다. 인터페이스 개선은 3구간이 끝난 뒤의 별도 백로그 항목으로 둔다: 지금 섞으면 이관 배치마다 동작 변화 위험이 붙는다.
- **2구간**: 새 구현과 그 characterization test 를 추가하고 호출처는 그대로 둔다. 정의상 동작 변화가 0 인 가장 안전한 구간이다.
- **3구간**: 의존 그래프의 위쪽 소비처부터 옮기고 아래쪽 기반을 나중에 옮긴다 (역위상). 그래야 배치마다 독립적으로 green 이다. 서로 얽힌 내부 심볼은 같은 배치에 둔다. 배치 크기의 상한은 한 번에 리뷰할 수 있는 diff 다. 소비처가 새 경계를 참조하려면 모듈 의존성 선언이 먼저 필요하다: 그 선언은 이관 배치와 다른 커밋이다.
- **4구간**: 일반 참조, 모듈·네임스페이스로 한정한 참조 (`<모듈>.<심볼>`), 문자열 기반 참조 (리소스 이름, 리플렉션, 설정 키) 를 모두 grep 해 0 임을 확인한 뒤 지운다. 한정 참조와 문자열 참조는 컴파일러와 심볼 검색이 놓친다.

모듈을 새로 만들거나 등록하는 일은 리팩터링이 아니라 레일 설치다. 별도 커밋으로 먼저 넣는다. 프로젝트의 계층 검사 (경계 lint, 의존 규칙 스크립트) 가 이관을 막으면 그것은 프로젝트가 이미 내린 설계 결정이다: 목적지를 Phase 2 백로그로 돌려 다시 정한다.

## 중단과 인계

이 레일은 여러 세션에 걸칠 수 있다. 구간이 끝날 때마다 남긴다:

- 지금 몇 구간인가, 이관된 호출처와 남은 호출처 수 (grep 실측)
- 공존 중인 두 구현의 이름과 각각의 소비처
- 남은 배치 목록과 순서, 그 순서의 근거

이것이 없으면 다음 사람은 절반만 옮겨진 상태를 버그로 보고 되돌린다.
